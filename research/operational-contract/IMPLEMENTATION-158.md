# #158 — Internal source-qualified observation slice

**Status:** Internal trusted-local reference implementation; exact-revision acceptance evidence belongs to its reviewed PR and GitHub CI. Not an external/public observer release. **Contract owner:** [Shared operational semantics #75](../../docs/product/riesel/operational-contract.md), [implementation acceptance #158](https://github.com/aschenrot/riesel/issues/158). This is not a production/public observer service.

## Implementation, ownership and reason for reusing a type

A small internal, in-process `riesel_app::operational_observation::ObservationSnapshot` represents **facts rather than one global readiness state**. It is compiled under the existing `internal-publication` test feature; the normal public `riesel` SDK exports no new observation type, port, schema, capability, app exporter, authenticated client or management command.

- **Riesel runtime**: `RunningApp::internal_operational_observations()` samples the existing supervisor/task checks and returns the **actual** session-token generation, plus specific versioned `ResolvedCapability` bindings issued after provider metadata/contract validation. A verified local or managed binding is a binding fact, **not** an attestation that a public app interface exists, that the OS attempt was authenticated, or that future calls will work. If current checks fail, no success is projected.
- **Application's own listener**: `ObservationSnapshot::local_listener()` accepts a caller-supplied runtime-session reference and a numeric bound loopback socket with an explicitly named interface. Its scope is explicitly `AdapterReferenceOnly`, **not** an independently runtime-attested epoch; the runtime-owner constructor alone marks `RuntimeIssued`. An adapter could otherwise mint a token and falsely claim to be the runtime, so a later external consumer must independently verify the relationship. It attests that the participating adapter **observed a bind at that instant**. It is not a live perpetual socket probe, authenticated remote readiness or any application operation grant.
- **Unavailable authorities**: both producers emit `AuthorizedApplicationOperation` and `OsLaunchAttempt` as `Unsupported`, because neither producer has authoritative external principal/authorization evidence or an OS launch-attempt owner. Absence of a named subject is `Unknown`; failed local checks also produce `Unknown`, not falsely “stopped”. A previously observed fact becomes `Stale` if the runtime session is invalidated or its snapshot exceeds a five-second in-process monotonic-clock age.
- **Bounds, privacy and evolution**: maximum 64 facts/snapshot, each subject-label (including configured instance names) limited to 128 UTF-8 bytes; overflow and malformed labels are explicit errors, not silent truncation. Facts contain only typed provenance, versions, planned instance identity, numeric loopback addresses, and a nonsecret runtime generation. No raw error strings, credentials, HTTP request content, OS labels, process command lines, persisted history, serialized publication or background observer thread. Snapshots are on demand, not queried on each graph/ECS/Query frame. No cross-process/global clock ordering is inferred.

## Real consumers and negative evidence

1. **Headless Counter**: the existing **genuine managed Counter crash/recovery** fixture checks a provider's versioned binding as an observation issued by `Runtime`. It also checks that external application operation callability is `Unsupported` even though `Counter::value` works. A surviving old snapshot becomes `Stale` after real same-PID runtime recovery; the successor has a different runtime-issued generation. Dedicated `probe_internal_publication.py` requires a marker for this behavior.
2. **Persistent Todo**: the real Todo/SQLite SDK app creates a typed task, binds an OS-assigned numeric loopback TCP listener, performs a real TCP connection, and records a distinct `ApplicationAdapter` observation. The socket bind is `Observed` but an authorized app operation and a verified OS attempt remain `Unsupported`. When the actual Todo session ends, its listener snapshot becomes `Stale`. A fresh SDK session opens the same SQLite database and verifies the task survived; it may not reuse the old interface observation.

Previously integrated, **not reimplemented**: executable-vs-passive inspection `tools/xtask/src/smoke/operational.rs`, API `503 unavailable` vs `outcome_unknown` and real committed write after lost reply [#171](https://github.com/aschenrot/riesel/pull/171), browser uncertain mutation/reconciliation [#179](https://github.com/aschenrot/riesel/pull/179), graph/nested observers and linked Query model authority. The model does not overwrite or serialize any of these owners' existing state.

## Remaining #158 acceptance before full closure

This slice deliberately does **not** attest provider process liveness from OS launch-attempt identity, app handler start or publication agreement, external verified peer/callability, or a supported source-/freshness-qualified **foreground executable/CLI** observer. The runtime-created source only owns a session and validated bindings; a live service, verified OS owner, authenticated client or app-specific handler state needs an independent truthful producer. Add a real process-owner/foreground consumer only under a verified attempt scope, preserve passive metadata isolation, test missing-peer/stale/dead-backend cases against actual source authority, and require exact-head `cargo validate --check` plus `cargo smoke` prior to calling #158 complete.

The intentionally opt-in internal API is not a commitment to freeze a common public `OperationalContract` structure: the accepted #75 decision is **shared semantics with independent adapters**, not centralizing every owner or accepting an exporter.
